# CH30 — Campus Facility Insight (Excel Deliverable)

An Excel-based data analytics and visualization solution for the DS Sprint use case. Microsoft Excel is the primary deliverable (`outputs/CH30_Campus_Facility_Analysis.xlsx`), featuring a complete 12-worksheet analysis model, KPI cards, conditional formatting, 4 native embedded charts, PivotTable-ready summary tables, and data quality audits. An optional Streamlit dashboard is also retained for interactive browser inspection.

## Important data note

The CH30 PDF lists five files: `bookings.csv`, `facilities.csv`, `occupancy.csv`, `calendar.csv`, and `maintenance.csv`. It does not include the actual records. `generate_demo_data.py` creates **synthetic demo data** only so you can test the system end-to-end. Demo metrics and observations are not real campus findings and must not be submitted as actual results.

## Primary Deliverable: 12-Worksheet Excel Workbook

The core deliverable is located at:
`outputs/CH30_Campus_Facility_Analysis.xlsx`

It contains 12 dedicated worksheets:
1. **Read Me**: Project overview, workbook structure, instructions, and core data dictionary.
2. **Raw Bookings**: Original reservation records (875 rows).
3. **Raw Facilities**: Facility register with capacities, room types, and campus blocks (8 rows).
4. **Raw Occupancy**: Raw hourly occupancy logs covering 120 days (10,561 readings).
5. **Raw Calendar**: Academic calendar with workdays, events, and exam periods (120 rows).
6. **Raw Maintenance**: Campus maintenance logs and recorded downtime hours (33 rows).
7. **Cleaned Data**: Standardized, deduplicated master dataset with imputed counts (10,560 rows).
8. **Data Quality Checks**: Audits covering missing values, duplicate bookings, casing, and over-capacity readings.
9. **Feature Engineering**: Enriched dataset with calculated time periods, peak flags, and utilization categories.
10. **Pivot Analysis**: Summary tables ready for Excel PivotTables (facility, hourly, daily, exam, and downtime).
11. **Dashboard**: Executive visual dashboard with 7 KPI metric cards, performance table with conditional formatting, and 4 native charts.
12. **Business Insights**: Data-supported findings, root causes, and strategic space reallocation recommendations.


```powershell
python analysis.py
```

## How to Create Native PivotTables in Microsoft Excel

1. Open `outputs/CH30_Campus_Facility_Analysis.xlsx` in Microsoft Excel.
2. Go to the **Feature Engineering** sheet and click any cell in the table.
3. Click **Insert > PivotTable** in the Excel ribbon and click **OK**.
4. In the PivotTable Fields pane:
   - Drag `facility` or `facility_type` to **Rows**.
   - Drag `utilization_pct` to **Values** and set Value Field Settings to **Average** (Number Format: `0.0%`).
   - Drag `time_period` or `day_name` to **Columns** for multidimensional cross-tabulation.
5. Click **PivotTable Analyze > Insert Slicer** to add interactive slicers for `facility`, `type`, `block`, and `peak_period`.

If your provided CSVs use different column names, adapt the mapping in `analysis.py` before running. Do not mark synthetic demo files as actual assessment data.

## What the app does

- Normalizes facility IDs, removes duplicates, parses dates and numbers.
- Imputes missing occupancy counts using facility medians (global median fallback).
- Flags occupancy readings above capacity and caps the analysis count at known capacity when calculating utilization; raw count is retained.
- Aggregates booking counts and maintenance downtime.
- Builds utilization summaries, peak-hour analysis, exam-period comparison, and downtime summaries.
- Trains/evaluates a Random Forest classifier for low/medium/high utilization. The target category is derived from occupancy divided by capacity; metrics describe this classification task, not future occupancy forecasting.
- Provides a browser dashboard and downloadable Excel workbook with summary, cleaned data, charts/tables, and model metrics.

## Limitations

- Synthetic patterns are artificial and intentionally include a few data-quality issues for testing.
- Utilization depends on the quality and time coverage of occupancy readings.
- Facility-level downtime is merged as a total per facility, so this starter implementation is useful for exploratory analysis, not a causal estimate of downtime's impact.
- Model scores may be inflated by repeated measurements from the same facilities across time. For rigorous evaluation, consider a time-based split or group-aware validation.
- Excel Pivot Tables are not generated automatically; the workbook includes summary tables and a chart. You can create Pivot Tables in Excel from the clean data if your assessment requires them.
